# v0.1.9 performance patch validation — 2026-09-22

- **374 offline tests passed** against source and a fresh archive extraction.
- Plugin and skill validation passed. Archive contents match source byte-for-byte.
- Windows live checks passed for all six providers: activation, one short prompt
  in Passthrough, one in Direct, and successful shutdown of every owned session.
- All six activations used two metadata reads, down from three: pre-readiness
  verification and a shared post-readiness verification/capability snapshot.
- Regression tests cover local/PATH Node selection, paths with spaces, custom
  wrapper fallback, invalid/missing installations, all six verification adapters,
  and settings drift after readiness keeping activation gated.

## Production launcher measurements (seconds)

| Provider | Activation | Passthrough handoff | Direct handoff |
|---|---:|---:|---:|
| agy | 92.46 | 0.711 | 0.763 |
| claude | 21.03 | 0.836 | 0.827 |
| codex | 29.50 | 0.704 | 0.738 |
| copilot | 18.01 | 0.716 | 0.734 |
| cursor | 33.44 | 0.765 | 0.732 |
| grok-build | 10.66 | 0.766 | 0.770 |

These are single production-patch samples per mode, not latency percentiles.
Handoff means controller entry to the observed outgoing ACP session/prompt event;
the host's Submit-to-controller interval is excluded. Readiness timings exclude
quota presentation. Offline tests overlapped part of the live run.

Handoff fell from approximately 1.16–1.31 seconds in the baseline to 0.70–0.84
seconds in this run. Activation totals varied: several providers were slower
than baseline despite one fewer metadata read and lower launch overhead. Provider
startup and readiness variability prevent promising an overall activation-time
reduction from these single trials. The earlier controlled Codex launcher
experiment showed about a 43% handoff reduction.

No changes were made to private-event filtering, permission enforcement, native
command routing, session ownership, readiness challenges or quota presentation.
Persistent activation connections and nonblocking quota rendering remain follow-up
work. Live checks exercise the controller, not Desktop hook trust or rendered UI.

## Packaging correction released separately

The original archive matched its build working directory, but CRLF working files
and LF Git blobs produced different ZIP bytes. Comparing the archive with the
committed source found 45 differences, all line-ending-only. The original v0.1.9
archive and tag are preserved unchanged. Reproducible packaging and metadata
corrections ship in [v0.1.10](v0.1.10-validation.md).
