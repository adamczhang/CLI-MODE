# 0.1.8 historical validation — two voices, and a codebase audit

> Historical development record. Earlier release tags and archives were retired when v0.1.9 became the initial public release.

This is the historical audit snapshot from before the five-provider validation
and reliability fixes. Its access mappings, account restrictions and test counts
are not the current release certificate. Use the
[2026-09-22 validation report](2026-09-22-five-cli-validation.md) for final results,
including Cursor Auto support, supported permissions and Claude's quota block.

Historical scope: it supersedes and includes the 0.1.6 and 0.1.7 verification, so
every backend and every audit since 0.1.5 is covered here in one place.

## Codebase audit

### Static sweep

All 22 modules parsed and checked for dead code, unused imports, bare or broad
excepts, mutable default arguments and identity-vs-literal comparisons. No
bare excepts, no broad `except Exception`, no mutable defaults and no identity
mistakes were found. Fifteen flagged imports are deliberate re-exports (each
adapter re-exports `executable`, `public_event` and `PublicRelay` so the
controller can call them through `self.adapter`). Five were genuinely dead and
were removed.

### Behavioural probe

52 assertions over paths the unit suite did not reach, all passing after the
fixes below:

- **Relay** — partial text is held rather than emitted per chunk; a changed
  `messageId` flushes the previous message; an identical plan snapshot is
  suppressed while an emptied plan is still emitted; pending text flushes
  before a plan; repeated identical text is never deduplicated.
- **Event translation** — malformed plans (non-list entries, non-string
  content, unknown status), empty message text and empty envelopes all yield
  nothing rather than a guess; done and error events are recognised.
- **Command admission** — punctuation in a command name is accepted, a bare
  slash and a mid-sentence slash are not commands, an observed empty list
  refuses an unknown command, and an unobserved list admits so the agent can
  answer for itself.
- **Menu framing** — a 120-character label wraps inside the 40-character
  frame and the frame still closes; an empty choice list renders one page
  rather than crashing.
- **Message rendering** — provider markup cannot break out of the fragment,
  and a label containing markup is escaped.
- **Routing** — malformed state raises rather than silently defaulting to off,
  which is the intended stance; empty and whitespace-only messages are not
  controls.
- **Adapter input** — every backend refuses an empty, `None`, traversal-shaped
  or wrong-case model ID.

### Bugs found and fixed

| Bug | Impact |
| --- | --- |
| `'Antigravity did not complete successfully'` hardcoded in `controller.prompt()` | Every backend's dispatch failure named Antigravity |
| `'Unknown or unavailable Claude command'` hardcoded in `native_commands` | Grok, Cursor and Copilot users saw Claude named in refusals; Claude's terminal-only list was also applied to runtimes it is not a fact about |
| `tune()` set `entrypoint='agy'` and omitted `backend` | A pending tuning menu on any non-Antigravity agent carried the wrong entrypoint |
| Five dead imports | Dead weight in the per-message import path |

Each fix carries a regression test asserting the bound agent is named and no
other agent's label leaks into the message.

## Performance

Measured, not assumed. Menu rendering was never the cost: the ACPX subprocess
calls and the activation readiness prompt around a menu run in hundreds of
milliseconds to seconds, so menus are still rendered on demand rather than
precomputed. Precomputing them would require invalidation on catalog refresh,
saved-settings changes, hook readiness and page number for a sub-millisecond
gain.

| Path | Before | After |
| --- | --- | --- |
| Home menu, file reads | 22 | **10** |
| Home menu, render | 1.35 ms | **0.65 ms** |
| Activation menu | 0.42 ms | **0.20 ms** |
| Phase page | 0.17 ms | **0.16 ms** |
| Routing hook, per message | 101 ms | **87 ms** |
| Routing hook, off turn | — | 106 ms (pays the controller import, as intended) |

Two changes produced this. The registry was re-parsed on every lookup, so a
single home menu read `backends.json` twelve times; it is now read once per
process and shared with the ID and alias caches. And the routing hook, which
runs as a fresh process on every message, imported the controller
unconditionally; that import now happens only on an `off` turn.

The remaining ten reads are the five per-backend setup receipts, read twice
each. Those are mutable state written by `check_and_save`, so caching them
would need invalidation for 0.7 ms. `/help` remains the one precomputed menu.

## Live dispatch verification

One minimal prompt was dispatched through ACPX for each new backend, exactly as
`controller.prompt()` does it (owned session, prompt delivered via `--file`),
and the raw ACP events were replayed through CLI-MODE's own translator.

| Backend | Event kinds emitted | Relayed | stopReason | Activation gate |
| --- | --- | --- | --- | --- |
| Claude Code | `agent_message_chunk`, `available_commands_update`, `session_info_update`, `usage_update`, result | message, done | `end_turn` | **PASS** |
| Grok Build | `agent_message_chunk`, **`agent_thought_chunk` x30**, `available_commands_update`, `background_tasks`, `model_changed`, `response_completed`, `turn_completed`, result | message, done | `end_turn` | **PASS** |
| Cursor | `agent_message_chunk`, `available_commands_update`, `session_info_update`, result | message, done | `end_turn` | **PASS** |
| Copilot | `agent_message_chunk`, `available_commands_update`, `config_option_update`, `session_info_update`, `usage_update`, result | message, done | `end_turn` | **PASS** |

The activation gate is the exact condition `controller.prompt()` applies before
reporting success: no error event, `stopReason == 'end_turn'`, and at least one
public message or artifact. All four satisfy it, so activation can complete for
every registered agent.

Three things this settles:

- **Private reasoning is filtered in practice, not just in theory.** Grok Build
  emitted 30 `agent_thought_chunk` events for a one-word reply; none reached the
  relay. Its `background_tasks`, `model_changed`, `response_completed` and
  `turn_completed` events are likewise ignored rather than surfaced.
- **Every backend advertises its commands over ACP.** `available_commands_update`
  arrived on the first turn for all four: Claude 50 commands, Grok 32, Cursor 29,
  Copilot 33. The cached-list admission path therefore has real data to work with
  from the first turn onward.
- **Slash commands are expanded in-session.** Sending `/context` to Copilot over
  ACP returned the command's own output ("Context information is not yet
  available. Send a message first…"), not a model answer about the word. No
  literal-argv path is needed for these backends.

### Antigravity's `-p` requirement does not generalize

Antigravity needs its slash commands passed as a single literal `-p` argv item
because its **native CLI transport** rejects them in streaming-stdin mode. That
transport exists only because Antigravity's ACP session cannot expand commands.

The other four have no native transport: their commands travel as ordinary ACP
prompt text and the runtime expands them. This is confirmed by the Copilot test
above, by every backend advertising commands over ACP, and by the Claude adapter
source, which inspects the incoming prompt text for a leading command. Grok and
Cursor were not individually dispatched with a slash command; they use the same
mechanism, and an unadvertised command is refused before dispatch either way.

### Fixed by this audit

A dispatch failure reported **"Antigravity did not complete successfully"**
regardless of which agent failed, because the message was hardcoded. It now
names the bound agent, with a regression test asserting each backend's label
appears and no other backend's label leaks into the message.

### A passing gate is not a working subscription

The Cursor probe returned `Upgrade your plan to continue` as a normal agent
message with `end_turn`. Activation would therefore succeed and report the
agent ready, while every subsequent task returns the same refusal. CLI-MODE
verifies transport and settings, not entitlement: a provider that answers
politely with a paywall message is indistinguishable from one that answers with
work. Users on an exhausted or unentitled plan will see activation succeed and
the refusal arrive as the agent's reply.

## Frontend consistency audit

A systematic audit across all five agents checked **901 assertions**, covering:

1. A uniform adapter surface: every module exposes the same constants,
   functions and `Backend` methods, with `ID`, profile and registry agreeing.
2. The same documentation set per agent: backend guide, confirmation guide,
   ACPX guide, catalog and activation template.
3. Structurally identical activation menus: same heading, subtitle, display
   name line, `Model:`/`Effort:`/`Access:` labels and `1. Yes` / `2. Change`.
4. Shared access vocabulary, never invented, with any unoffered level
   explained in that backend's catalog.
5. Every phase of every agent rendering under the option cap, with the right
   title, a Back row, a single Exit row, and each advertised choice shown once.
6. Home, first-start and setup menus under the cap.
7. Every rendered block inside the 40-character frame with exactly one exit row.
8. Help covering every agent's controls and default model.
9. No cross-backend settings leakage in any direction.
10. Utilization claims matching each backend's actual capability.

### Inconsistency found and fixed

Access options were ordered differently per agent. Antigravity and Claude Code
listed `prompt, auto-edit, allow`, mirroring the order their runtimes
advertise, while Grok Build, Cursor and Copilot listed `allow, prompt`. Every
backend guide specifies allow first, so the default choice sat at position 3
for two agents and position 1 for three.

Fixed at the presentation layer: `frontends.phase_options` now sorts access
into one documented order for every backend, so a future backend inherits it
regardless of catalog order. Catalogs still record the advertised order as
observed. Two regression tests cover the ordering and the requirement that an
unoffered level is explained rather than silently missing.

### Bug found and fixed by the audit

`frontend()` and `first_time_check()` passed the conversation's saved settings
into whichever backend page was opened, regardless of which backend accepted
them. Opening `/cli grok` while bound to Claude rendered "Model: Opus 5" and
"Access: Bypass permissions" on the Grok Build page, and an Antigravity-shaped
record would raise on a newer page because it has no `accessName`. Saved
settings are now scoped to their owning backend, with regression tests both ways.

## Menu option cap

Every menu is capped at **ten selectable rows**, counting the caller's
navigation rows, `X. Exit`, and the paging rows. Longer lists page with
`> Next page (n of m)` and `< Previous page (n of m)`, numbering stays
continuous, and `B. Back` remains the previous phase.

Choice menus are generated in code rather than assembled by the host, which is
what makes numbering and paging deterministic. Cursor's 39 models render as 8
pages of 5: with three reserved rows plus up to two paging rows, five is the
largest page that still honors the cap. The strict reading of "ten options
total" was chosen deliberately.

`checks/test_pagination.py` sweeps 1–59 items against 0–4 reserved rows and
asserts no page exceeds the cap and every item appears exactly once, in order.

## Control matrix

Every control was exercised against every agent under both accepted prefixes:
134 assertions, all passing. Coverage includes each agent's menu and bind forms
(canonical id and alias, upper case, whitespace), stop/off, all four tuning
verbs with and without a choice, help, menu exit, and negatives that must stay
ordinary text.

`$` is accepted on every command rather than `/cli` alone, so `$help` opens
help. `?` is **not** a prefix; `?cli` and `?help` are ordinary text. A complete
token is required, so `/client` and `$helpme` are not controls.
`checks/test_control_matrix.py` keeps this covered.

## Not verified here

- A clean-machine guided install of any backend's prerequisites, including the
  approved popup and browser sign-in.
- A dispatched passthrough turn for any new backend, its public relay in Codex
  Desktop, and artifact presentation. The relay path is shared with Antigravity
  and covered offline through real pipes, but an installed-host run is separate.
- A Claude subscription exposing a separate Opus or Sonnet weekly window. The
  helper iterates advertised windows, but this account reported only `session`
  and `weekly_all`.
- Whether Grok, Cursor or Copilot ever emit `available_commands_update`. Until
  one is observed, a slash command is admitted and the agent answers for itself.
- Copilot's sign-in state. The CLI has no status subcommand, so the probe pairs
  a successful version call with a stored token directory rather than asking
  the service.
- Whether another Cursor account or plan advertises a different model set.
- Image input over ACP for Cursor. The capability is advertised, but CLI-MODE's
  sender is text-only.
- Hook trust and execution inside Codex Desktop, as for every release.
