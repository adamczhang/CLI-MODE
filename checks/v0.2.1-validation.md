# v0.2.1 release validation — 2026-09-23

## Scope

A follow-up to [v0.2.0](v0.2.0-validation.md): Claude Code's zip and GitHub installs end the same.
Codex's skill moved to `plugins/cli-mode/codex/skills/`, `/cli shortcuts` was added, and the install
instructions were unified. See the [changelog](../CHANGELOG.md). No agent, menu, settings or relay
behaviour changed.

## Evidence

- **600 tests pass** from source (`python -m pytest checks`). They include `checks/test_agent_docs.py`,
  which ties `AGENTS.md` and `CLAUDE.md` to this version and to paths that exist, and the new
  `/cli shortcuts` tests.
- **The Codex golden record** changed only in the skill's path: its 90 occurrences of
  `skills\cli-mode\SKILL.md` became `codex\skills\cli-mode\SKILL.md`, and the rest of the record is
  byte-identical.
- **Codex loads the skill from its new path.** In a throwaway `CODEX_HOME`, `codex debug prompt-input`
  lists `cli-mode:cli-mode` from `…/codex/skills/cli-mode/SKILL.md`, which costs no model call.
  `checks/codex_install_smoke.py` passes, with 89 files verified across the installed copies.
- **Both Claude Code routes end the same.** `checks/claude_install_smoke.py`, in a throwaway
  `CLAUDE_CONFIG_DIR`, gives this for both the repository (GitHub) route and the zip's
  `install-claude.ps1`:
  - `Skills (2)  cli, d`;
  - six Claude hook handlers;
  - eight CLI-MODE prompts answered at 0 model turns, `/cli shortcuts` included;
  - afterwards, the same slash commands: `cli`, `d`, `cli-mode:cli`, `cli-mode:d`.

  The installer's shortcuts step (now `scripts/claude_shortcuts.py`) leaves a user's own `d.md`
  untouched.
- **Archives:** `cli-mode-codex-0.2.1.zip` (84 files) and `cli-mode-claude-0.2.1.zip` (89 files).
  Rebuilds are reproducible.

## Limits

- The live Claude Code runs recorded for v0.2.0 were not repeated. This release changes installation and
  packaging only, and the install checks above cover both.
- Cursor remains verified offline: its account is plan-limited.
- The GitHub channels (`--ref v0.2.1` and `@v0.2.1`) are checked in throwaway configurations after the
  tag is pushed.
