# Post-tag live validation — 2026-09-22

## Scope

The starting point was `main` at `fdcb052` (`v0.1.11`). This pass exercised
the post-tag fixes on Windows with ACPX 0.18.0 and real Claude Code, Codex CLI,
Grok Build, Antigravity, Cursor, and GitHub Copilot accounts. The tagged archive and tag were
not changed, installed, pushed, or published. The fixed candidate archive is
kept separately from the release archive.

The live harness calls the source `SessionStart` and `UserPromptSubmit` hooks
with isolated state and workspaces, then drives the same controller and detached
queue worker used by the plugin. It does not verify that Codex Desktop has
trusted or rendered the updated installed plugin.

## End-to-end result

All six agents passed the first home menu and prerequisite scan, Direct as the
default route, activation through the displayed model/effort/access choices,
local help and settings controls, quiet/activity preference, and one owned main
session. Stage 1 was dispatched while stages 2 and 3 were captured behind it;
all three settled in FIFO order without a second provider session or a rewritten
prompt. The three-stage challenge implemented a duration parser, record
summarizer, and JSON command line interface. Independent API, CLI, invalid-input,
and agent-test checks passed for every workspace. An unpredictable marker was
retained across all three turns.

Passthrough captured an ordinary prompt and returned the expected reply. After
switching back to Direct, an ordinary host prompt stayed with Codex. `/cli stop`
closed ownership, repeated stop was harmless, off-state `/d` was not forwarded,
and a new binding answered a fresh probe. Final shutdown left no owned sessions
or inflight operations.

## Defects and changes

The tagged source initially failed first activation for Codex and Claude:
strictly resuming an ACPX placeholder session before a provider conversation
existed returned an internal error or resource-not-found. New bindings now use
ACPX's normal CLI empty-session recovery for the first readiness probe, save
the resulting provider identity, apply settings through the running shared
owner, and verify a second readiness response. All user turns and later
readiness checks remain strict and identity-pinned. All six real providers
passed after this fix.

Long public silence previously offered no measured wait information. Captured
and submitted receipts now record timestamps; `observe` reports worker state,
age of the current receipt status, and time since the last public event or
dispatch. The presentation guidance permits a neutral elapsed-time update
after 30 seconds of silence, at most once per minute, without suggesting that
the agent is making progress. A focused test covers these fields without
calling a provider. The elapsed-time change is presentation-only and was added
after the first four coding sequences; the Cursor/Copilot coding and all six
cancellation sequences exercised the current code.

A Grok first-time sign-in scan once returned a negative result and a subsequent
read-only scan passed. The setup flow already exposes `R` to recheck; the
successful coding sequence used a passing scan. No account setting was changed.
