# v0.4.0 release validation — 2026-09-28

## Scope

0.4.0 brings AUTO mode to Claude Code (its default) beside DIRECT, and tunes it as a partnership: Claude Opus leads
and checks, and an agent, ideally a cheaper engine from another provider, does the work worth handing over. It also
carries each agent starting once on its chosen settings, canceled turns shown at once, the `/cli usage` fixes and
parallel checks. See the [changelog](../CHANGELOG.md).

## Evidence

The usage runs used `checks/claude_usage_live.py`: each prompt in a fresh throwaway project, a fresh headless Claude
Code session and freshly started agents, judged by hidden acceptance tests the agents never saw, byte-exact data
files and exact answers computed in advance. The last rounds ran the CLI-MODE Claude Code had installed
(`--installed`), with Claude Opus 5.5 as host.

- **AUTO against Claude alone, a cheaper engine** (`--set multi`, Antigravity on Gemini 3.8 Flash, host at Medium):
  work moved off Claude 36% (2.5k-token prompt, 3 parts), 60% (12.5k, 4 parts), 71%, then 77% once handoffs sent
  together woke Claude once (50k, 5 parts), and 66% on a 5k sequential job; every hidden test, data file and answer
  right. Claude alone took 16.7 min on the 50k prompt and saved one of five data files wrong; AUTO took 6.5 min.
- **AUTO with Claude Code agents** (same prompts): 1.9, 2.3 and 2.7 min against 1.7, 5.7 and 16.7 min alone.
- **Behaviour:** every independent part went to its own agent, each started once; the sequential job stayed whole
  (one handoff); parallelism rose with the parts, to 3.07; 5 wake-ups became 1 and the host's model calls 13 became 5.
- **Parallel starts** (`--set par`, three independent parts, Claude Code agents): 3 agents instead of 2, parallelism
  2.05 instead of 1.39, 0.5 s waiting instead of 88 s.
- **Earlier AUTO rounds** (`--set shop|fleet|fleet5|hot`, Codex, Antigravity and Claude Code agents): the partnership
  rule took AUTO from 1.77x Claude alone's time to 1.28x on three 5k tasks; after a wake-up Claude made no tool
  calls; the working-folder note went with an agent's first task only.
- **Live AUTO checks** (`claude_auto_mode_live.py --matrix`, Codex): simple prompts stayed with Claude, complex ones
  were handed off in two tool calls each, and two agents wrote on separate claims at once.

## Checks

- `python -m pytest checks -q -p no:cacheprovider -n auto --dist loadgroup`: see the release commit (935+ passed);
  the Codex golden record is unchanged by AUTO, which is Claude Code's alone.
- `checks/claude_install_smoke.py` and `checks/codex_install_smoke.py`: pass.

## Known limits

- A cheaper engine is slower than Claude on small prompts (5.5 min against 1.7 on 2.5k tokens) and saves less there
  (36%): AUTO pays off from about 5k tokens of prompt up.
- With Claude Code agents, the agents' work stays on Claude's plan: that pairing buys speed, not usage.
- The Claude Code CLI signed out twice on its first request after a long idle stretch (an OAuth refresh that failed);
  `claude auth login` restored it. The usage test checks the sign-in before each run and stops at the first failure.
- Cursor was not re-tested (no plan usage left at the time).
