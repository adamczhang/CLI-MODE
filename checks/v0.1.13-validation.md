# v0.1.13 release validation — 2026-09-22

## Scope

This release packages the changes after `v0.1.12`: CLI-MODE's own lockfile-pinned
ACPX install and folder-based discovery, access labels and permission-stop
messages, per-route hook instructions, cancellation of the first readiness
probe, credential reading that is checked against `acpx config show`, Windows
job objects for submitter processes, the controller module split, the
single-table `/help`, and untracked release archives.

## Verification

- Full source test suite: **468 tests passed** in 290.6 seconds.
- Full suite from a fresh extraction of the 0.1.13 archive, with an empty
  workspace and isolated Codex home and state: **468 tests passed** in 288.7
  seconds. The report is at
  `%USERPROFILE%\AppData\Local\Temp\cli-mode-fresh-package-s0f0f1jp\evidence.json`.
- The package builder compared all **91 archive entries** with normalized
  source bytes and found six backend registrations. The archive contains the
  ACPX `package.json` and `package-lock.json` and no `node_modules`.
- The release archive has SHA256
  `550fa888038089af5eddf9abdc8723fe8947063a99191d7f6f3c8feb0daf9bef`.
- Python compilation, Node syntax checks for all three runtime modules and
  `git diff --check` passed.

Specific evidence for the new behavior, all against the real ACPX 0.18.0 runtime
and the offline fixture agent unless noted:

- **Installer:** the setup script's `Install-Acpx` function ran `npm ci` from
  the shipped lockfile into a temporary folder, and its check then reported the
  CLI-MODE-owned copy. The setup scan reported the owned copy and, with none
  present, the global fallback.
- **Permission stop:** a Prompt-access turn that requested permission ended
  with `PERMISSION_PROMPT_UNAVAILABLE` and the new message, was recorded as
  failed, and the next turn completed.
- **First-prompt cancel:** with the fixture holding the readiness probe, the
  cancel signal ended activation promptly. The same test fails after 25 seconds
  without the fix. Stopping during that probe shut down cleanly.
- **Killed worker:** killing a controller process mid-turn ended its bridge
  within seconds. The session owner stayed alive, and the fixture received no
  cancel until one was sent explicitly.
- **Credentials:** the values the bridge read matched the real
  `acpx config show` global and project precedence, and every mismatch case
  was refused.
- **Controller split:** an AST comparison found all 39 methods unchanged except
  `ensure_pump`, whose worker command now names `controller.py` explicitly.
- **Hook size:** measured on the same scenarios, delegated turns went from 5,106
  to 2,851 characters, help from 4,251 to 1,256, the routing-mode menu from
  4,393 to 2,249 and the inactive home menu from 4,066 to 2,743. Tests cap each
  route's size.

## Limits

No live provider accounts were used for this release. Live behavior of the
six providers was last recorded for v0.1.12. The guided installer was tested
by running its ACPX function on its own, not through a full Codex Desktop setup
run. It was not run against this machine's real `%LOCALAPPDATA%`, where the
global ACPX remains in use until setup installs the owned copy. The job-object
tie applies on Windows only. Installed Codex Desktop hook trust and rendering
were not verified.
