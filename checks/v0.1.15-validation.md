# v0.1.15 release validation — 2026-09-22

## Scope

This release packages the changes after `v0.1.14`: the quote-free Windows hook
launcher, exact view references, Markdown mid-turn updates with one final view,
Codex theme tokens in views and menus, a settled one-step stop with wait
guidance, and session close and cancel through the warm bridge.

## Research

- **Codex's hook runner** (`codex-rs/hooks/src/engine/command_runner.rs`) runs a
  Windows hook as `COMSPEC` (else `cmd.exe`) `/C` with the command passed as one
  raw, quoted argument, and places it in a job object that preserves descendants.
- **Codex Desktop 26.917** (the installed app bundle) recognizes an inline view
  from a line of its own reading `visualize{...}` or `::codex-inline-vis{file="..."}`,
  outside code fences. Mid-turn agent messages are grouped with reasoning in the
  collapsed work log, and the bundled visualize skill says to place references
  only in a final response. Each view is a sandboxed frame that loads the kit's
  CSS and HTML and Floating UI scripts.
- **Your recorded session of 22 September** (before v0.1.14): a `/d` turn took
  277 seconds, most of it model steps (observe polls, self-chosen sleeps,
  hand-written log readers, format calls); `/cli stop` needed two `off` calls and
  a sleep; the model read the visualize skill three times in six prompts.

## Measurements

| Measure | Before | v0.1.15 |
| --- | --- | --- |
| Windows hook, per prompt | 444 ms (PowerShell launcher) | 130 ms |
| `off` with the offline agent | 1.10 s (three ACPX processes) | 0.09 s (one bridge request) |
| Views per delegated turn | one per batch | one, at the end |
| Hook instructions, delegated turn | 2,514 characters (v0.1.14) | 2,738 |

Activation (about 3.8 s) and a turn (about 1.25 s) with the instant offline agent
are unchanged from v0.1.14.

Tests cover: the hook launcher run as Codex runs it, as `cmd /C`, `cmd /D /S /C`
and with no shell, with spaces and `&` in the plugin path, plus exit-code
propagation; reference lines on menus and nested activation views; Markdown
updates, the single final view, its last-message rule, quiet mode and the defusing
of agent-written view references; theme tokens with fallbacks; `off` waiting for
a live submitter but reporting stranded work at once; close through the bridge
with no ACPX process; cancel falling back to ACPX when the bridge is busy.

## Limits

No live provider accounts or installed Codex Desktop were used. Two behaviors
need a live check there: that the new hook launcher runs under the installed
Codex, and that the model posts mid-turn Markdown and ends with the reference
line as instructed. Whether a view referenced mid-turn would render was inferred
from Codex's code and skill, not observed.
