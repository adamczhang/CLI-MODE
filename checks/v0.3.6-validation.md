# v0.3.6 release validation — 2026-09-26

## Scope

0.3.6 lets an agent below Allow access ask for a permission in the host chat and be answered with
`/cli approve [name] [always]` or `/cli deny [name]`, and sends files and pasted images attached to a `/d` to the
named agents (copied into `Agent_Working_Folder/<NAME>/attachments/`, removed when the agent closes). See the
[changelog](../CHANGELOG.md).

## Probes before the code

- **Claude Code attachments:** a message with a file and an image attached, in the desktop app. The file arrives
  as an `@"…\uploads\<session>\<id>-README.md"` mention before the typed text; the image is not in the text and is
  saved only as `uploads\<session>\<id>-image.jpg`, about 40 ms before the prompt. The transcript lists each
  message's files (`inlined_image_paths`, file attachments).
- **Codex attachments:** a throwaway `CODEX_HOME` with a trusted hook that saves its input, driven through
  `codex app-server` with a text item and a `localImage` item. The hook receives only the typed text, and the
  session log has no user message yet when it runs. Codex desktop sessions list attached files, pasted images too,
  as a "# Files mentioned by the user:" block above "## My request:" in the text itself.
- **ACPX permissions (Grok Build, live):** at `--approve-reads --non-interactive-permissions fail` the turn stops
  at the agent's `session/request_permission` (kind `edit`, title ``Write `…hello.txt` ``, raw input), which the
  session journal records with ACPX's reply. A per-prompt `--permission-policy` answered the retry `allow-once`,
  but Grok retried under a different title, so rules approve kinds, not titles. ACPX shared sessions refuse
  `onPermissionRequest`, so a request cannot be held open for the user.

## Evidence

- **Offline:** the full suite passes from source (`python -m pytest checks -q -p no:cacheprovider`), including
  `checks/test_approvals_attachments.py` (both hosts' attachment formats, copies, the Claude uploads rule with a
  transcript that does or does not already end with the prompt, approve/always/deny routing, the policy) and three
  `checks/test_acpx_runtime.py` cases through a real ACPX 0.18.0 and the test agent: the stop asks with the
  agent's own request and keeps it on the agent; an approved kind is answered `allow`; a kind the approval does
  not cover escalates, stops the turn and asks again.
- **Codex golden record**, re-recorded (170 steps, 35 route kinds): only the help card's new
  `/cli approve|deny   answer its ask` row moved, in its text, menu and view. No step changed its route.
- **Packaging:** `scripts/package_plugin.py` builds `cli-mode-codex-0.3.6.zip` (90 files) and
  `cli-mode-claude-0.3.6.zip` (95 files); both install smokes pass.
- **Live, Grok Build at Prompt access** (the controller and routing hook from source, a throwaway project):
  `/d` to create a file stopped with "Grok GRO-C7 asks to edit files: …hello.txt"; `/cli approve` sent it on and
  it created the file ("Created `Agent_Working_Folder/GRO-C7/hello.txt` with exactly: hi from grok"). The first
  build's approval failed at ACPX's own file-write check, which reads only the mode; approved turns now run at
  approve-all under the rule, which this run verified. A `/d` with an `@"path"` file attached was answered from
  the file's contents, and the copy was gone after closing.

## Limits

- Pasted images in the Claude Code desktop app are found by the uploads-folder rule, checked offline against the
  shapes recorded in the probe; a live `/d` with a pasted image in the installed plugin was not run.
- Codex attachments follow the desktop app's "Files mentioned by the user" text seen in its sessions; a pasted
  image sent through `codex app-server` as a separate item does not reach the hook and is not forwarded.
- The GitHub channels at `v0.3.6` are checked in throwaway configurations after the tag is pushed.
