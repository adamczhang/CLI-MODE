# CLI-MODE v0.1.8

> Historical development record. Earlier release tags and archives were retired when v0.1.9 became the initial public release.

Release documentation updated 2026-09-22.

CLI-MODE supports Antigravity CLI, Claude Code, Grok Build, Cursor and GitHub
Copilot through one persistent selected agent. This release combines the
Direct/Passthrough routing and the two-voice presentation update with fixes
found during live five-provider testing.

## Changes

- Add `/cli mode`: Passthrough is the initial default; Direct sends only requests
  beginning with `/d` or `$d` to the active CLI. Other prompts stay in Codex.
- Show the current mode and a Change routing mode option on every agent defaults
  page. Use the shared menu styling and return to setup without activation.
- Keep routing selection independent of CLI on/off state and provider settings.
- Strip the Direct trigger before native command validation. Preserve provider
  `/help`, Antigravity teamwork alias expansion and native conversation handoff.

- Prevent repeated Windows PATH refreshes from breaking ACPX and hook launches.
- Confirm cleanup when session creation fails before registering an owner.
- Require a fresh readiness marker so quota or upgrade refusals cannot activate routing.
- Distinguish recoverable file-tool errors from prompt failures, and handle
  ACPX's historical permission-denial exit code without hiding current denials.
- Load persisted native-command catalogs, reject unavailable commands and report
  successful commands that return no public text without inventing a response.
- Name the selected backend correctly in setup, errors and prerequisite results.
- Keep relayed agent replies in the host's normal text colour with a concise
  agent attribution; reserve the accent for CLI-MODE's own messages.
- Add repeatable research and control validation runners for all five providers.

## Access changes

Cursor supports **Allow only**: its native writes bypass ACP permission callbacks,
so Prompt cannot be enforced. Antigravity supports **Allow and Prompt**: its
advertised Auto-edit mode still has file writes denied by ACPX. Unsupported
choices are rejected even when present in old catalogs or saved ACP sessions.
Claude Code's Auto-edit mode passed live validation and remains available.

## Validation

- **334 offline tests passed**, both from source and a fresh package extraction.
- All five providers completed three connected research prompts, retained context,
  saved a checklist and completed close/reopen in the earlier full pass.
- Final-build research passed for Antigravity, Grok, Cursor Auto and Copilot.
  Claude passed turn 1, then hit its session quota during turn 2; its earlier
  research sequence and subsequent supported control checks passed.
- All five passed supported settings, permission, idle-memory, native-command,
  cancellation and shutdown checks. All 49 scoped ACPX test records were closed.
- Cursor Auto and Copilot's default model worked on the existing accounts. A
  Cursor alternate model required an upgrade and was left blocked. No account
  upgrades, reset credits or paid fallback models were used.

The routing additions have fixture coverage across all five adapters, including
command validation, exact payloads, session continuity and Antigravity native
command arguments. No new live teamwork execution is claimed. See the
[routing and menu validation report](direct-mode-validation.md).

Full Desktop menus, hook trust and compaction integration remain unverified;
controller and fixture results do not certify those flows. Clean-machine setup,
provider-managed background teams and every native workflow are also outside
this validation. See the [complete report](2026-09-22-five-cli-validation.md)
for the evidence, tested versions and remaining limits.
