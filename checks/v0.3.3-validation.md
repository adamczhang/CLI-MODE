# v0.3.3 release validation — 2026-09-25

## Scope

0.3.3 fixes one leak: every Antigravity start left about 1.25 GB in `%TEMP%`. Antigravity's ACP server
(`agy_acp_server.exe` 1.1.1) is a PyInstaller one-file program that unpacks 8,247 files into a new `_MEI`
folder on every start and deletes it only when it exits by itself; the managed launcher's kill-on-close job
object, and setup's `terminate()` after its sign-in check, end it before that. The launcher
(`plugins/cli-mode/scripts/acp-login.py`) now gives each server its own `TMP`/`TEMP` with a held lock file
and removes the folders of ended launchers on every start. See the [changelog](../CHANGELOG.md). Nothing
else changed, so the [0.3.2 validation](v0.3.2-validation.md) covers the rest of the code.

## Evidence

- **Offline:** the full suite passes from source (`python -m pytest checks -q -p no:cacheprovider`, 746
  tests), including the Codex golden record (unchanged) and four new tests in
  `checks/test_installer.py` (`ManagedLauncherTemp`): a running launcher's folder is kept and an ended
  one's removed; a launcher killed outright (TerminateProcess, as the job does) has its folder removed by
  the next start; leftover lock files are removed unless held; `main()` hands the server its own TEMP.
- **Packaging:** `scripts/package_plugin.py` builds `cli-mode-codex-0.3.3.zip` (88 files) and
  `cli-mode-claude-0.3.3.zip` (93 files); both install smokes pass in throwaway configurations.
- **Live, against the real server,** in a runtime folder whose path is as long as
  `%LOCALAPPDATA%\CLI-MODE\setup\runtime` (the unpack fails past Windows' 259-character path limit, and the
  deepest unpacked path is 120 characters below the `_MEI` folder):
  - each start unpacks fully into its own folder in about 9 s;
  - killing the launcher, as ACPX does, ends the server (the job object) and leaves its folder;
  - the next start removes that folder in the background;
  - no `_MEI` folder appears in `%TEMP%` throughout.

## Limits

- A launcher configured by hand in `~/.acpx/config.json` is preserved by setup and does not get the fix;
  the release notes say so.
- Copies left by earlier versions stay in `%TEMP%`; the release notes show how to find them.
- The GitHub channels at `v0.3.3` are checked in throwaway configurations after the tag is pushed.
