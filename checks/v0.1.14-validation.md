# v0.1.14 release validation — 2026-09-22

## Scope

This release packages the responsiveness work after `v0.1.13`: the `relay`
command and its nested view, larger message batches, complete commands in hook
instructions with a session-start preload, activation that returns its own
confirmation with one readiness prompt, a reused bridge process with cached ACPX
configuration and post-turn session reporting, a lingering worker, lazy adapter
loading in the hook, and trimmed skill documentation.

## Measurements

All against the real ACPX 0.18.0 runtime with the offline fixture agent, which
answers instantly, so these times are CLI-MODE and ACPX overhead only.

| Measure | v0.1.13 | v0.1.14 |
| --- | --- | --- |
| Activation with non-default settings | 6.7 s, 11 ACPX processes, 2 readiness prompts | 4.0 s, 1 readiness prompt |
| One delegated turn | 2.5 s (dispatch after 0.4 s) | 1.3 s (dispatch after 0.08 s) |
| Hook instructions, delegated turn | 5,106 characters (v0.1.12) | 2,514 |
| Hook instructions, home menu | 4,066 (v0.1.12) | 3,061 |
| SKILL.md | 21,358 bytes | 6,462 bytes |
| Model tool calls per relayed update | 3–5 (observe, write text, format, render) | 2 (relay, render) |

Most of the remaining 1.2 seconds of a warm turn is ACPX's own owner round trip
and turn settlement. The model tool-call counts come from the documented
workflows, not from observing Codex.

Specific evidence for the new behavior:

- **Relay:** tests cover the nested `<details>` structure (work, plan and tool
  groups), escaping of provider HTML, batching of streamed fragments into one
  view, the immediate first call with the passing line, an empty result after a
  quiet wait, draining a settled log past the 500-event page size, and quiet mode.
- **Worker linger:** a lingering worker took a message captured while it idled,
  then exited after the linger.
- **Bridge server:** all ACPX runtime tests pass through the reused bridge,
  including cancellation, owner loss, a killed submitter and cursor repair.
- **Activation:** `bind` returned its confirmation with exactly one usage lookup,
  started before activation finished. Readiness tests now expect one prompt.
- **Hook:** tests check which rule groups each turn carries, size budgets, the
  session-start preload and the complete commands.

## Windows hook launcher

A direct `cmd.exe` hook command measured 147 ms against 444 ms for the PowerShell
launcher. Under the three ways a host might hand the command to `cmd.exe`, the
quoted form failed whenever the command arrived as one argument (the inner quotes
become `\"`), and quote-free forms failed for a plugin path containing `&`. The
PowerShell launcher handles all of these, so it was kept.

## Limits

No live provider accounts were used. Relay views, the preload and the complete
hook commands were not observed in an installed Codex Desktop; how Codex Desktop
renders nested `<details>` in its inline visualization surface was reported by
the user from a separate test, not verified here. Live provider behavior was last
recorded for v0.1.12.
